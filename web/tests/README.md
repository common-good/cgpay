# Tests

Three kinds of tests:

- **Vitest** — pure-function and server-module unit tests. Fast, no browser, no DB.
- **Playwright (plain specs)** — legacy end-to-end tests in `tests/e2e/`. Being replaced gradually by Gherkin features.
- **Playwright + Gherkin (`playwright-bdd`)** — new end-to-end tests: `.feature` files in `tests/features/` with step definitions in `tests/steps/`. Write new E2E tests this way.

## Layout

```
tests/
├── unit/       # Vitest tests — run with `npm run test:unit`
│   ├── drupal-password.test.ts    phpass prefix dispatch + guard behaviour
│   ├── env.test.ts                Required-env check, PHP URLs and cookie domain derived from PUBLIC_PHP_BASE_URL
│   ├── php-client.test.ts         Server-to-server calls to PHP (config and error handling)
│   ├── php-grants.test.ts         Grants client for PHP /cgpay-grants
│   └── rate-limit.test.ts         Rolling window + lockout semantics
├── e2e/        # Legacy plain Playwright specs (project "chromium")
│   ├── login.spec.ts              Login page contract + protected-route redirect
│   └── grants.spec.ts             Grants create-form client contract
├── features/   # Gherkin .feature files (project "bdd")
├── steps/      # Step definitions. fixtures.ts defines the fixtures and exports Given/When/Then
└── support/    # Helpers shared by steps (test-db.ts: client for the PHP test endpoint; accounts.ts: the standard test accounts by nickname)

.features-gen/  # (in web/) generated by `bddgen`; gitignored; never edit
```

## Running locally

```sh
# Unit tests — quick, run these constantly during development
npm run test:unit
npm run test:unit:watch

# E2E — slower (builds + starts the preview server). Runs `bddgen` first.
npx playwright install chromium   # once, per machine
npm run test:e2e
npm run test:e2e:ui               # opens the Playwright UI
npx playwright test --project=bdd # Gherkin features only
npm run bddgen                    # recompile features after editing a .feature or step

# Everything
npm run test
```

## Gherkin (BDD) tests

- Import `Given`, `When`, `Then` from `tests/steps/fixtures.ts`, not from `@playwright/test`.
- The `testDb` fixture runs before every scenario and POSTs `op=initialize` to the PHP test endpoint (`testops()` in `cgmembers/rcredits/forms/api.inc`). That resets the standard test accounts (`.ZPA` to `.ZPI`: Abe, Bea, Cit, Dee, ...). The endpoint refuses to run on production or stage. Scenarios refer to accounts by first name, like the old app's cucumber suite.
- The endpoint URL defaults to the local WAMP, `http://localhost/cg/cgmembers/api/`. Override with `TEST_API_URL`.
- One worker only (`workers: 1`): the app's rate limiter is in-memory and the test DB is shared. Keep scenarios independent; set up state in fixtures, never rely on a previous scenario.
- The BDD project is skipped when `CI` is set, because CI has no PHP test endpoint.
- The BDD project browses `http://localhost:4173` (override with `E2E_BASE_URL`), not `127.0.0.1` like the plain specs: a signed-in flow needs the SSO cookie, whose domain (derived from `PUBLIC_PHP_BASE_URL`) is `localhost` locally.
- The login endpoint allows 5 attempts per minute per IP (in-memory limiter), so a run can contain at most 5 sign-in attempts per minute; spread more across minutes or raise the limit for test runs.
- The plain grants specs need `E2E_FAKE_USER=1` in the server's environment (CI sets it); export it before `npm run test:e2e` locally, or put it in `.env`.
- To skip the rebuild on each run, start `npm run build && npm run preview -- --host 127.0.0.1 --port 4173` once; local runs reuse a server already on that port.
- Model for step vocabulary: the legacy PWA's cucumber suite (`tests/` at the repo root).

## What's covered vs. what isn't

The unit tests cover the pieces that don't touch external systems: phpass
prefix dispatch and input guards, env validation and derivation, the PHP client
and grants client (with `fetch` mocked), rate-limit window/lockout
semantics. They run in <1s and are safe in CI without any env.

The E2E tests cover the login-page contract (labels, placeholder, error path)
and the protected-route redirect (unauthenticated visitor to `/` gets bounced to
`/login`). They do **not** cover the full sign-in round-trip because that needs
a real MariaDB with a known user row plus the PHP SSO backend — both awkward
to reproduce in CI. That path is smoke-tested manually against staging on
every deploy; when it makes sense, extend `login.spec.ts` with a
`test.describe.serial('signed-in flow')` guarded by an env flag pointing at a
throwaway test DB.

## CI

`.github/workflows/test.yml` runs both jobs on every PR that touches `web/**`.
Unit tests must pass. E2E has retries on failure and uploads the Playwright
report as an artifact so we can inspect flaky renders. Only the plain specs run
in CI for now (see Gherkin tests above).
